# 前端接口代码生成工具 - 开发计划

## 概述

本计划旨在实现一个自动化接口代码生成工具，根据后端 Spring Boot 的 OpenAPI 文档自动生成前端 API 调用代码、请求参数类型定义和响应参数类型定义。工具将生成三个核心文件：`api.js`（API 函数定义）、`req.js`（请求参数类型定义）和 `resp.js`（响应参数类型定义），并集成到现有 Vue 3 + Vite 前端项目中。

### 项目目标
1. **自动化生成**：减少手动编写 API 代码的工作量
2. **类型安全**：通过 JSDoc 提供 IDE 类型提示
3. **前后端同步**：确保接口定义与后端保持一致
4. **提高开发效率**：快速响应接口变更，减少错误

### 技术栈
- **运行时**：Node.js (>= 16.0.0)
- **核心库**：handlebars (模板引擎)、axios (HTTP请求)
- **辅助工具**：prettier (代码格式化)
- **测试框架**：Vitest (与项目现有测试框架一致)

### 输出目录
- `frontend/src/services/generated/` - 生成的代码文件
- `frontend/scripts/generate-api/` - 生成工具源代码
- `frontend/scripts/generate-api/openapi.config.js` - 配置文件

## 风险评估与应对

### 风险 1：OpenAPI 文档不规范或缺失
**可能性**：中
**影响**：高
**描述**：后端提供的 OpenAPI 文档可能缺少必要的字段、格式不正确或不完整
**缓解措施**：
1. 使用 swagger-parser 进行严格验证，提供明确的错误信息

## 集成与部署

### 开发工作流集成
1. **本地开发**：
   - 在 `package.json` 中添加 scripts：
     ```json
     {
       "scripts": {
         "generate:api": "node scripts/generate-api.js",
         "generate:api:watch": "node scripts/generate-api.js --watch",
         "dev:with-api": "npm run generate:api && vite",
         "build:with-api": "npm run generate:api && vite build"
       }
     }
     ```
   - 开发人员可随时运行 `npm run generate:api` 更新 API

2. **预提交钩子**：
   - 可选的 Git 预提交钩子，确保生成的代码与 OpenAPI 文档同步

### CI/CD 集成方案
1. **生成验证**：
   - 在 CI 流水线中添加生成步骤
   - 验证生成的代码是否与当前提交一致

2. **示例 GitHub Actions 配置**：
   ```yaml
   name: API Generation Check
   on: [push, pull_request]
   jobs:
     generate-check:
       runs-on: ubuntu-latest
       steps:
         - uses: actions/checkout@v4
         - name: Setup Node.js
           uses: actions/setup-node@v4
           with:
             node-version: '18'
         - name: Install dependencies
           run: npm ci
         - name: Generate API
           run: npm run generate:api
         - name: Check for changes
           run: |
             if git diff --name-only | grep -q "src/services/generated"; then
               echo "生成的 API 代码需要更新"
               echo "请运行: npm run generate:api"
               exit 1
             fi
   ```

### 版本控制策略
**方案：提交生成的代码**
- **优点**：
  - 构建过程简单，无需生成步骤
  - 代码审查可看到实际生成的代码
  - 版本历史清晰
- **缺点**：
  - 仓库中会有生成的代码，可能增加噪音
  - 需要确保生成一致

**决策**：建议提交生成的代码，因为：
1. 前端项目规模适中，生成的文件数量有限
2. 简化构建流程，避免环境依赖
3. 便于代码审查和问题排查
